# 游戏参数导表

鱼图鉴详情中的“最爱鱼饵”由 `鱼.xlsx` 的 `favorite_bait_id` 指定。填写 `工作台.xlsx` 中已有的鱼饵 ID，且该鱼饵的 `bait_type` 必须包含鱼的 `preferred_bait_type`；修改后重新导表，详情卡会更新图标和名称。

## 界面文本与中英文

玩家可见的文字统一放在 `文本.xlsx` 的“文本”页：`id` 是稳定引用键，`中文` 与 `English` 分别是两种语言的内容，`来源备注` 帮助定位使用位置。修改译文后运行一次导表，游戏下次启动就会读取 `data/text/texts.json`。设置窗口的“中文 / English”按钮可切换语言，选择会保存在本机。已经打包的版本需要重新打包才能得到新表。

新增文字时，先在文本表追加一行并填写两种语言；ID 推荐用 `ui.功能.用途`，旧 ID 不要改名。脚本用 `TextDB.text("ui.功能.用途")` 取文字；带 `%d`、`%s` 等格式参数的文案，两个语言必须保持相同的占位符，再在取值后用 `%` 填参数。静态场景节点保留中文 `text` 供编辑器预览，并在下一行加 `metadata/l10n_text = "ui.功能.用途"`；占位符、提示、窗口标题分别使用 `l10n_placeholder_text`、`l10n_tooltip_text`、`l10n_title`。

植物、鱼、鱼饵、鱼竿、成就及建筑名称按 `catalog.类别.道具ID.字段` 引用，例如 `catalog.fish.fish_001.display_name`。新增配置行时也要在文本表补齐相应 ID 和英文；修改配置表中的中文名称时，同步修改文本表的中文列。新手引导 JSON 使用 `title_id`、`text_id`。导表会检查中文硬编码、静态节点绑定、ID 缺失、中英文名称一致性和占位符；可先运行 `python3 excel/export.py --check`。

## 本轮成长数值

植物解锁累计收获门槛、鱼竿升级费和商店参数已按核心成长方案调整；鱼表、鱼售价保持原值。`建设.xlsx` 的“参数”页控制小屋二至四级，以及第 3～7 块地各自的开垦费用。每次操作只解锁一块地，按从右到左的顺序推进；第 3～5 块地需要小屋 2 级，第 6～7 块地需要小屋 3 级。导表时费用写入 `cottage_levels.json` 与 `upgrades.json`；建设参数必须为非负整数，保留全部八个 key。请勿直接修改导出 JSON 中的费用。

2～8 小时为待新档验证的设计目标，不是实测结论。

每个工作簿的“参数”页是一张独立模块配置表。`key` 后的“中文备注”列是参数的简短中文名称，末尾 `description` 列提供详细解释；这两列不会导出为游戏参数。只修改 `value` 列；`key` 与 `type` 是程序接口，不能随意改名。数值请保持 Excel 数字类型，`min` / `max` 是导表时的取值校验。

在 macOS Finder 中双击 `一键导表.app` 即可导表；完成后会弹窗提示，详细结果保存在同目录的 `导表运行日志.txt`。也可以双击 `导表.command`，或在项目主目录运行：

```bash
./excel/导表.command
```

命令会先检查所有工作簿；全部通过后写入 `data/config/*.json`、`data/text/texts.json`，并把 `植物.xlsx`、`鱼.xlsx`、`工作台.xlsx`、`成就.xlsx` 导出到 `data/catalog` 中的作物、鱼、鱼饵、鱼竿和成就 JSON。也可运行 `./excel/导表.command --check` 只校验。导表工具也可直接用 Python 3 执行 `excel/export.py`；无需安装第三方库。Godot 在下次启动时读取导出的 JSON，无需手动修改脚本。已打包的程序不会读取项目外部的 Excel；要让分享版生效，导表后需重新打包。

工作簿分工：角色（移动、游荡、其他工作操作时长）、钓鱼（抛竿时间与鱼饵权重）、种植（施肥、默认生长参数、播种/浇水/收获的单格操作时长）、工作台（鱼饵配方、每种鱼饵的制作时长和鱼竿升级）、成就（图鉴成就条件和两种图标）、随机事件（事件间隔）、时间存档（离线与保存节奏）、界面（桌面尺寸和提示时长）、商店（收购刷新、栏位、倍率、升级金币）。商店表中除一级 3 个栏位外的当前数值均为可修改的临时值，正式数值待策划确认。`植物.xlsx`、`鱼.xlsx`、`成就.xlsx` 的“数据”页分别是一行一个品种或成就；`工作台.xlsx` 的“鱼饵”“鱼竿”页分别是一行一个道具。第 1 行是程序字段，第 2 行是中文字段说明，第 3 行起可以增删品种。每行的“中文备注”供策划记录用途，不会导入游戏。

## 图片资源索引

游戏内的种植卡和植物图鉴读取 `植物.xlsx` 的 `icon_resource`，地块三个阶段读取 `seed_resource`、`leaf_resource`、`mature_resource`。鱼图鉴、商店及鱼掉落读取 `鱼.xlsx` 的 `icon_resource`，必要时可同时修改该表的 `icon_region_x/y/width/height` 裁切范围。工作台、钓鱼选择和鱼饵图鉴读取 `工作台.xlsx`“鱼饵”页的 `icon_resource`；鱼竿读取同工作簿“鱼竿”页的 `icon_resource`。成就图鉴分别读取 `成就.xlsx` 的 `icon_locked` 与 `icon_unlocked`。

图片列填写项目内完整资源路径，例如 `res://assets/hd/ui/icon_bait_simple.png`；文件必须已放入 `assets`，导表会检查是否存在。当前 28 种鱼饵都指向同一张通用鱼饵图。日后把某一行改为新图片路径，双击导表工具并重新启动游戏即可生效；不要直接改导出的 JSON。

`工作台.xlsx` 的 `craft_seconds` 是角色在工作台完成一次制作所需秒数，由鱼饵品种决定；制作数量只倍增材料消耗和鱼饵产出，不倍增制作时间。每种鱼饵可填写最多三种材料及各自的每批消耗；`charges_per_batch` 是每批产出数量。鱼竿页的 `tier` 决定升级顺序，`upgrade_cost` 是升级金币。修改这两页后导表并重启游戏即可生效，不要直接改导出的 `baits.json` 或 `rods.json`。

新增植物时，填入唯一英文 `id`、名称、成本、成熟秒数、产量、鱼饵类型及贴图路径。`harvest_amount` 是每个小格的常规收获量，`plant_cost` 也是每个小格的播种成本；整块 3×3 种满时分别计算九次。`mutation_chance` 是一块地种满同一作物时的变异概率（0 到 1），变异时其中两个上下相邻格合成一株巨型植株，这两格各按双倍产量计算。`种植.xlsx` 的 `unwatered_growth_multiplier` 控制种子和幼苗未浇水时各阶段的生长时间倍率。`mature_visual_width` 与 `mature_visual_height` 控制成熟单株显示宽高（地块本地坐标），导表后下次启动生效。`initially_unlocked` 填 Excel 布尔值 TRUE 可让新旧存档直接解锁该作物。种子、叶子、成熟贴图须是单株透明图片，程序会将其铺到 3×3 静态格心；`icon_resource` 用于播种选项。`bait_links` 可留空，或填已存在的鱼饵 ID，多个以英文逗号分隔。若想新增专属鱼饵，还需另改鱼饵目录；单纯新增作物不依赖此项。当前地块外观固定为种子、叶子、成熟 3 阶段，所以 `growth_stage_count` 必须填 3。

植物解锁条件也在 `植物.xlsx` 的“数据”页配置：`unlock_crop_1` / `unlock_amount_1` 至第 3 组分别表示前置植物 ID 和该植物的**累计收获数量**。最多填三组；填多组时必须全部达标才解锁。前置植物必须在本表更靠前的行，导表会检查不存在的 ID、重复条件、无条件锁定及循环依赖。只有 `initially_unlocked=TRUE` 的植物可以不填条件，且初始解锁植物不能同时填写前置条件。累计收获数量按实际获得数量记录，卖出、制作鱼饵或消耗库存不会倒退；存档会保存进度。默认新档只有小麦可种，种植窗口点选灰色卡片可查看各前置植物当前进度。旧存档保留已经解锁的植物；测试完整新链请使用 GM 重置存档。

新增鱼时，填入唯一英文 `id`、名称、4 种品质之一、偏好鱼饵类型、基础权重、售价及图鉴贴图路径。`icon_region_width` 与 `icon_region_height` 都填 0 表示使用整张贴图；现有鱼共用大图局部，所以保留了裁切坐标。新鱼会自动进入对应品质的鱼竿候选池及图鉴页。资源路径须以 `res://assets/` 开头且文件实际存在；导表会检查 ID、类型、数值和路径。场景节点位置、存档版本和固定的七块地仍是结构配置。

品质底色统一读取道具的 `rarity`：`common` 普通为绿色、`good` 优秀为蓝色、`rare` 稀有为紫色、`epic` 史诗为金色。植物在 `植物.xlsx` 修改，鱼在 `鱼.xlsx` 修改，鱼饵和鱼竿在 `工作台.xlsx` 修改。工作台、图鉴和商店卡片中的 `RarityBack` 是可手动调整的静态节点，四张底图位于 `assets/hd/ui/rarity_*.png`。

`工作台.xlsx` 的鱼饵 `bait_type` 支持一种类型，或用英文分号连接两种类型，如 `grain;root`。只有鱼的 `preferred_bait_type` 命中鱼饵任一标签，鱼才进入候选池；鱼竿品质上限仍会过滤高品质鱼。鱼饵正好是 `鱼.xlsx` 的 `favorite_bait_id` 时，再乘以 `钓鱼.xlsx` 的 `matching_bait_weight`（默认 1.5）。`good` 及以上鱼饵会让已入池的稀有、史诗鱼基础权重乘以 `high_rarity_bait_rare_epic_weight_multiplier`（默认 5），无法越过标签或鱼竿限制。天气表的雨天钓鱼速度、雪天作物生长速度倍率均默认为 2，可在 `天气.xlsx` 调整并重新导表。

`天气.xlsx` 还配置大风出现权重、作物成熟时间倍率（默认 1.2）、阵风间隔与帧时长、雪堆出现进度。`牧场.xlsx` 的“参数”页配置四种动物各自产出所需分钟数；动物持续不饥饿才累计时间，饥饿时进度归零。“农产品”页配置鸡蛋、牛奶、羊毛、猪肉的名称、对应动物、售价、品质和图标路径，导表到 `data/catalog/pasture_products.json`。商店的“产品”页读取这张表，并按所选种类全部出售。

种植弹窗的“整块地为一组”默认勾选：同一块地先逐格播种，再逐格浇水；整组已种植的小格都成熟后逐格收获。取消勾选后，只处理点中的小格；若从地块空白处打开，则处理首个空小格。自动重复种植沿用该小格的分组设置。

角色寻路以 `StaticWorldStrip/PathLayer` 中实际可见的土路 Sprite 位置为准。`角色.xlsx` 的 `road_travel_cost` 越小越倾向走土路，`route_corner_clearance` 控制绕开碰撞体的转角余量；旧 `safe_lane_y` 和 `rest_lane_threshold_y` 已停用。
