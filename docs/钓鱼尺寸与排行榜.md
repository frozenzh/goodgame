# 钓鱼尺寸与每周排行榜

## 尺寸规则

- 每次钓获都会按鱼的品质，从 `excel/钓鱼.xlsx` 的 `*_size_min_cm` 与 `*_size_max_cm` 范围抽取整数厘米。相同品质的鱼共用范围。
- 抽取使用离散三角权重：越靠近中间越常见；最小值和最大值概率较低，但都能实际抽到。
- 鱼图鉴卡片左上蓝色「小」表示钓过该品质的绝对最小尺寸；右上金色「大」表示钓过绝对最大尺寸。这两个标记位于 `scenes/ui/FishCodexCard.tscn`，可分别移动、改色。右侧详情同时显示该鱼的个人最小和最大记录。
- 记录存入游戏存档的 `fish_size_records`，出售鱼不会清除记录。

## 运行本地共享榜单

从项目主目录执行：

```sh
python3 tools/leaderboard_server.py --host 127.0.0.1 --port 8765
```

游戏的榜单入口位于 `PondWindow` 的第三个一级页签「排行」。服务地址由 `excel/钓鱼.xlsx` 的 `leaderboard_url` 控制，改表后运行 `python3 excel/export.py`。本地服务默认监听 `http://127.0.0.1:8765`，数据写入 `server_data/leaderboard.sqlite3`。其他机器要共用榜单时，把服务运行在可访问的主机上，并将 URL 指向该主机。

榜单按 UTC 周一 00:00 开新的一周，每位玩家只显示当周最长的一条鱼，最多显示前 10 名。客户端只上传超过自己当周最高纪录的钓获。离线新纪录会暂存在本地存档；连接恢复后，只补交本周纪录。窗口显示「未连接」时，不会把本地记录冒充服务器排行。

## 后续接 Steam

客户端通过 `LeaderboardService` 调用 `POST /v1/catches` 和 `GET /v1/weekly?limit=10`。当前服务是开发用接口：玩家 ID 由本地生成，服务会校验鱼种及对应品质的尺寸范围，但没有可信身份认证，也无法证明钓获由未修改的客户端产生。接 Steam 前，应在正式服务器校验 Steam 身份票据，并在可信服务端记录钓获；届时保持排行榜返回字段 `player_id`、`display_name`、`fish_id`、`size_cm`、`caught_at`，游戏 UI 不必重做。
