# 地块已安排种植与收获状态实现方案

2026年11月4日，主策划批准实现。目标：点击后立即确认哪些地块已接单，等待期间持续可见，完成、取消或失败后准确清除。只增加任务反馈，不借本需求改变种植成本、劳动时长、收获产量与自动复种策略。

## 一 状态与视觉

每块地一个静态 PendingBadge，放在 PlotTile 场景的可调锚点，随地块移动缩放。含种植行、收获行，每行有小图标、沙漏和文字；不新增点击遮罩，忽略鼠标，不改变图片像素热区。层级高于作物、低于窗口提示；缩放后不得挡住邻地、货币、角色头顶进度。

- 已安排种植：种子/芽图标＋沙漏，文字“待播种”；单一作物时在详情显示“待播种 · 草莓 · 6格”，混种显示“待播种 · 2种作物 · 6格”。地上不提前画真实种子，以免误认已完成。
- 已安排收获：篮子图标＋沙漏，文字“待收获”；成熟作物保持原样，详情显示“待收获 · 9格”。
- 同地同时存在播种与收获命令，两行同时显示，不相互覆盖。若未来播种尚未真正进入队列，仅设置了持续种植，则不显示待播种。
- 执行中：已有劳动动画与进度条继续使用；对应行切为“播种中”或“收获中”。移动到目标途中仍为“待…”。同地仍有后续排队命令时，详情分别显示正在执行和剩余等待数。
- 完成该格后立即减计数，最后一项结束则隐藏对应行；播种/收获结果和资源反馈沿用现有机制。若只剩浇水命令，播种标记应消失，不把浇水当成待播种。
- 主画面只放短文字，不常驻长名称与格数；完整信息在原有地块进度/详情区域展示。图标不用emoji，优先复用现有资源，缺少时制作简单匹配像素风的小图。

## 二 唯一数据来源

以 JobManager 的真实命令队列为唯一权威，不在点击回调维护额外 pending 布尔值，也不另存一套表现状态。当前已有 get_pending_commands、get_pending_tasks、get_started_command_id、job_queue_changed，以及 task_id/task_action/task_grouped，需复用。

提供统一的只读查询（建议 get_plot_work_status(plot_id)），返回种植/收获各自的等待格集合、作物分布、当前执行格与动作。聚合后一次广播或刷新给全部地块和操作面板，避免每帧每块重扫队列。只读查询不得扣钱、创建任务或改变队列。

plant_cell/harvest_cell 的 target_id 按 plot_id:cell_index 解析；兼容遗留 plant/harvest 的整地块目标及已迁移的批次结构。使用真实地块ID，不按玩家右到左编号推算。一个单格同类动作去重计数，分组任务展开的子命令不能被重复计入。遗留整地块命令如无法精确估算，则显示任务状态不虚构格数。

get_started_command_id仅表示命令已开始时，要核实角色是否还在行走；“中”状态必须绑定角色真实劳动开始事件/状态。无法判断真实开工前宁可维持“待”，不能抵达前假报执行中。

## 三 提交与重复操作

仅入队成功的地块显示标记，同帧或下一帧更新，不能等角色走到才出现。入队返回已有ID属于已经安排，不重复扣费或增加计数。已有预付批量种植和退款机制必须保留。

按钮针对实际可操作范围判断：全部目标已安排时显示“已安排种植/已安排收获”并禁用对应重复提交；只有部分目标已安排时，保留“补种未安排空格/安排剩余收获”，只提交未安排的合法格。不能因一格排队就锁住整块地的其他合法操作。不同作物争用同一空格时不能重复预付，用户可通过现有取消任务方式更换；不新做自动替换扣费逻辑。

批量收获后，每块成功接单地立即显示标记；队列容量、金币不足或其他原因导致部分接单时，提示“已安排X块地，Y块未安排：原因”，不能报全部成功。没有任何成功入队时不显示等待标记。

## 四 生命周期与异常

任务增加、批次合并、开始劳动、完成、取消、移除失效任务、载入、重置时均重算。仅调整任务顺序不影响待办标记，只更新执行指向。根据现有信号补齐必要事件，禁止依靠持续轮询掩盖漏事件。

取消整批清除对应标记，保留其他真实任务；部分取消只减少对应格数。失败命令按现有逻辑移除并一次性说明原因，批量同原因合并提示；若仍有有效任务则继续显示。外部修改、目标已被收获/播种等失效情形不能残留永久沙漏。

关闭窗口不清除任务或标记；读档待队列迁移完成后重建，角色未恢复劳动前显示等待。重置清空。关闭持续种植不自行取消已经入队的播种，除非当前规则本就如此；界面明确区分“持续种植”偏好和本轮真实任务。

## 五 文件与验证

建议改动 JobManager 的状态聚合接口和事件、PlotTile.tscn/plot_visual.gd 的静态标记、main_ui.gd 的按钮与详情。先读 docs/项目档案.md、当前进度.md、决策记录.md及适用规范，按最新代码接入，保留其他工作区改动。文案进入当前TextDB链路。

必须验证：
1. 单格/整块/混种/七块批量提交立刻显示正确状态和地块归属。
2. 连点不重复命令、不重复预付；部分排队仍能安排剩余合法格。
3. 同地收获和后续播种、单格完成到整批结束时计数准确；只剩浇水不显示待播种。
4. 行走期间显示待办，实际劳动时才显示进行中；移动队列、取消与失败无残影。
5. 队列满/钱不足/部分成功反馈真实；存读档与重置不留假标记。
6. 持续种植只勾选未入队时不显示待播种；自动生成的真实播种命令正常显示。
7. GUI核查七块地与缩放场景的遮挡、透明背景和点击，提交等待播种/等待收获/两状态共存截图。

交付可运行代码、必要逻辑与场景回归测试、截图及验证说明。无GUI或未跑的检查需如实标明，不把脚本解析通过等同视觉通过。本轮不要求重做整地块批量劳动系统。
