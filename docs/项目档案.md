## 用户长期工作方式

- 持续显示的 UI、弹窗、建筑与卡片模板应有可在编辑器直接调位置和尺寸的静态节点；运行时只填数据、切换状态或补充超出模板数量的条目。改逻辑时清理失效节点。目录最多四层文件夹。
- 玩家可见文本使用 `文本.xlsx` 的 ID 与 `TextDB`；配置以 Excel 源表为准。翻译、数据或资源索引改动后导表，再启动游戏。
- 用户自行做游戏内测试；必要的导表校验、场景加载和针对性规则检查可由开发窗口执行。
- 生图使用内置生图模型，不使用 `ui-ux-pro-max` 生图。旧要求：新窗口默认模型为 `gpt-5.6-sol`。

## 常用校验

```bash
python3 excel/export.py --check
/Users/frozen/Downloads/Godot.app/Contents/MacOS/Godot --headless --path /Users/frozen/myfavorite --editor --quit
/Users/frozen/Downloads/Godot.app/Contents/MacOS/Godot --headless --path /Users/frozen/myfavorite res://tests/FishingTagPoolTest.tscn
```

直接用 `--script res://tests/fishing_mvp_rules_test.gd` 曾因自动加载类 `DropService` 未被该启动方式识别而失败；这不等同于主场景运行失败。优先使用主场景或场景级测试验证。
