# 天气系统 V1：策划与实现规格

日期：2026-10-27。状态：主策划批准实现。适用工程：`/Users/frozen/myfavorite`，游戏《塘边小日子》。

## 1. 目标与范围

为桌面挂机提供舒适、可辨认的环境变化，并验证一个轻度玩法机会：雨天继续使用合适鱼饵，偏好收益略有提高。天气不能成为催促上线、强迫等待或打断劳动的机制。

本版必须完成：晴/雨/雪、自然轮换、平滑过渡、环境音、天气文字与规则提示、表现设置、存档兼容、一个雨天鱼饵偏好修正、开发调试入口和验收。暂不做阴天、雾、风、雷暴、季节、预报、天气限定鱼、积雪覆盖、积水、浇水、减速、作物增产或新货币。

本规格是对旧 `docs/GAME_DESIGN.md` 中“不做季节天气”的显式增量变更。旧文档有已过时的地块数、收获与离线规则；不得借天气开发恢复旧规则。其余行为以当前代码、README 和最近用户要求为准。

## 2. 已核实的工程约束

- Godot 4.x，项目标记 4.7，Compatibility 渲染；主场景 `scenes/main/Main.tscn`，透明无边框 1280×168，原生子窗口独立显示。
- 世界场景 `scenes/world/StaticWorldStrip.tscn`；视觉不能把主窗口透明空白填成不透明矩形，不能影响建筑按图片像素点击或原有桌面交互边界。
- `TimeManager` 管理 tick 与离线时长；`GameState` 管理持久状态；`SaveManager` 当前版本 8，通过 `game_loaded` 等事件驱动初始化。
- 钓鱼当前仅在线运行，每杆开始消耗一个饵；中断与离线有现成退饵逻辑。保留这些规则。
- `scripts/systems/fishing_system.gd` 中 `build_candidate_pool()` 先按鱼竿品质和鱼饵标签过滤；鱼的 `favorite_bait_id` 正好是当前鱼饵时，才应用 `matching_bait_weight=1.5` 的额外倍率。
- 参数遵循 Excel→JSON→GameConfig 链路；遵守根目录 `UI_ASSEMBLY_STANDARD.md`，持续存在的界面和视觉根节点须落在可编辑 `.tscn` 中。

## 3. 天气轮换的确定规则

天气 ID 为 `sunny`、`rain`、`snow`，显示为晴天、雨天、雪天。

| 参数 | 默认值 | 语义 |
| --- | --- | --- |
| duration_min_seconds | 600 | 每段持续时间下限 |
| duration_max_seconds | 900 | 每段持续时间上限，含端点 |
| sunny_weight | 50 | 抽取晴天权重 |
| rain_weight | 30 | 抽取雨天权重 |
| snow_weight | 20 | 抽取雪天权重 |
| transition_seconds | 4.0 | 视觉与音频淡变时长 |
| rain_matching_multiplier | 1.10 | 雨天对匹配鱼饵的额外权重倍率 |

新档和重置从晴天开始，持续时间在范围内均匀抽取。到期抽取下一种天气，排除当前天气后按剩余权重归一化，避免连续重复；因此权重是“候选抽取权重”，不是长期天气占比承诺。

天气按真实 Unix 时间到期，不受游戏窗口焦点影响。休眠/离线后如已过期，只抽取一次新天气，以当前时间为新段起点，不逐段补算，不触发历史奖励。未过期则保留当前天气和原到期点。系统时间回拨时，将剩余时长钳制到 0～duration_max_seconds，避免天气无限延长；损坏值、未知 ID、非正区间回退为新的晴天段并记录警告。

存档应保存当前 ID、段起始与到期时间及独立天气 RNG 状态（按 JSON 能可靠还原的格式，例如十进制字符串），重进游戏不得重新抽取未到期天气。天气 RNG 与鱼、事件 RNG 分离。加载后直接显示目标天气，首帧不闪晴天；仅在线切换时淡变。到期处理需幂等，同一边界不因多次 tick 重复抽取。

## 4. 唯一玩法变化：雨天偏好更明确

只有雨天影响鱼的候选权重，不改变钓鱼时长、耗饵、数量、售价、品质门槛或候选资格。晴天和雪天使用现有权重。

公式：最终权重 = base_weight × 原有鱼饵偏好倍率（匹配才乘）× 天气倍率（仅雨天且匹配才乘 1.10）。例如基础权重 10 的匹配鱼：晴/雪为 15，雨天为 16.5；不匹配鱼仍为 10。这里是权重提升，不是最终概率加 10 个百分点。后续仍按权重总和归一化。

按现有代码的鱼饵偏好匹配规则判断，不新增硬编码目标鱼名单。所有鱼原有可捕获条件保持不变，天气不解锁鱼竿等级以外的鱼，普通天气可以完成全部图鉴。

每杆开始时将 `weather_id` 和天气倍率快照写入现有 `fishing_cast`，该杆按快照结算。中途切天气不追溯，不额外扣饵；旧存档的在途杆无快照时按倍率 1.0。正常 UI 候选预览使用当前天气；实际抽鱼必须使用该杆快照，不能直接读当前天气。快照是完整的有效规则：同一杆结算时不得因热改参数改变倍率。保留静态候选池函数的既有调用兼容性，可通过默认参数扩展。

提示文字：雨天“雨天：当前鱼饵偏好的鱼权重额外提高 10%，仍受鱼竿品质限制。”晴天“晴天：常规钓鱼。”雪天“雪天：常规钓鱼，天气不影响作物生长。”百分比从配置生成。界面避免“稀有率+10%”等错误表述。

## 5. 表现方案

以粒子/程序动画为主。雨使用细短线、斜向下落；雪使用小点或小雪片、缓慢下落和轻微横向摆动。优先选择与 Compatibility 兼容的 `CPUParticles2D`，也可使用有固定数量上限的自绘粒子；不可为每个雨点每帧创建新节点。无需新增大型帧动画或外部 AI 素材服务依赖。

在世界场景放置独立可编辑 `WeatherVisual` 场景实例，内置雨、雪、色调/云影等静态节点，位于世界之上、HUD 和弹窗之下。遮罩或裁剪到世界窄条的约定展示范围；不能下到桌面其他区域或原生子窗口。保留原有透明背景，不用全屏不透明 ColorRect；如使用 shader，正确保留 alpha，不能整体污染其他窗口。

晴天保持现有画面基准；雨天轻微降亮偏冷；雪天稍冷且保持可读性。默认雨不超过 100 个、雪不超过 50 个可见粒子，低表现档分别不超过 40/20；参数可调。雨雪切换时允许两组短暂淡入淡出，不得每帧重启粒子。移除旧过渡 Tween，连续强制切换不能叠加失控。效果可忽略鼠标事件，不新增遮挡点击的 Control。

## 6. 音频、界面与设置

雨天提供柔和无缝雨声，晴天和雪天默认静音，不为凑数量增加风声。音频随 4 秒过渡淡入淡出，经独立 Weather 总线并服从主音量；暂停/关闭音效后无爆音。优先复用来源明确的已有素材；没有合适素材时可离线生成低音量、经过滤波的噪声循环 WAV，提交资源并说明生成来源，无需网络下载。禁止每帧在主线程生成声音。

主场景 Overlay 增加静态 `WeatherIndicator`（文字即可，图标可选），放在现有 HUD 空闲位置；鼠标悬停显示规则提示，不能挡住货币、建筑入口或设置。设置窗口增加静态控件：“天气效果：标准/简化/关闭”和“天气环境音：开/关”。默认标准、声音开启且低音量；偏好存档。关闭视觉或声音只改变表现，天气逻辑、文字和雨天效果仍生效，设置旁明确说明。

不新增原生窗口或独立天气面板，不调整游戏整体高度，不弹强制天气通知。调试入口仅编辑器或 debug build 可见：晴/雨/雪强制切换、立即到期。强制切换重建本段持续时间并保存；正式发行版不能让玩家用该入口挑天气。

## 7. 建议模块与改动边界

- 新 `scripts/systems/weather_system.gd`：唯一逻辑权威，处理初始化、到期、独立 RNG、快照查询与信号。由主场景实例化并通过现有服务方式访问；确有启动顺序需要才选择 autoload，避免重复实例。
- 新 `scripts/world/weather_visual.gd` 与 `scenes/world/WeatherVisual.tscn`：只消费天气状态和偏好，不决定规则或保存状态。
- `GameState` 增加 weather 状态与表现偏好；`SaveManager` 按届时实际版本递增并增加兼容迁移。旧档缺字段初始化晴天，绝不重置经济、地块、图鉴或任务。
- `EventBus` 新增天气变化信号，建议 `(previous_id, current_id)`；到期时逻辑立即切换，4 秒仅是表现过渡。监听者首次连接后主动查询当前状态，避免错过初始化信号。
- 钓鱼系统接入每杆快照，候选权重查询与真实结算分清。启动初始化必须在离线处理和 `game_loaded` 顺序下安全执行。
- 新 `excel/天气.xlsx` → `data/config/weather.json`，接入 `excel/export.py` 和 GameConfig 模块。除上表参数外，导出粒子数量、雨雪速度和漂移、音量等调整项；字段含中文说明、类型和边界校验。导表失败不能部分覆盖配置；更新 `excel/README.md`。
- 更新 README、DATA_SCHEMA 与 UI 静态节点规范中的新增节点说明。旧 GAME_DESIGN 只明确标注天气范围被本规格替代，不趁机重写其他历史规则。

开发者可在不改变本规格语义的情况下调整文件组织和接口名；发现真正冲突先说明具体冲突，能安全解决的常规工程问题自行处理。保留工作区已有改动，不重置或覆盖其他功能。

## 8. 实现顺序

1. 配置及校验、状态与迁移、轮换逻辑；提供可注入时间和 RNG 的逻辑入口。
2. 钓鱼快照和权重、边界自动化检查。
3. 场景视觉、雨声、静态天气文字和设置。
4. 调试切换、场景与回归检查、截图和最终交付说明。

## 10. 交付内容与试玩判断

交付可运行代码、场景、音频、Excel 和导出配置、迁移、必要测试、运行命令、截图路径与未验证项。禁止只交技术方案。测试日志和截图可放临时目录，最终摘要引用实际产物。

主策划试玩重点：雨雪是否舒适、是否遮挡桌面；不看提示能否辨认三种天气；看到雨天提示后是否愿意尝试另一种鱼饵。若玩家倾向停止正常钓鱼等雨天，下轮优先降低倍率或移除加成，不靠加天气限定奖励补救。本版不以新增天气数量作为完成指标。
