# 设置功能评估与优化策划

日期：2026-11-05。角色：主策。对象：《塘边小日子》当前 Godot 项目。

## 1. 评估结论与边界

**现有设置具备基础入口，但尚未形成可靠的桌面常驻控制中心。优先补齐行为一致性、声音控制和位置反馈，再考虑扩展功能。** 不建议以增加大量通用选项或重新制作整套美术作为第一轮目标。

本报告以当前 `.tscn`、`.gd`、配置与文本导出文件为依据，仅输出评估与策划，不修改游戏功能，不执行自动测试或游戏测试。用户补充要求前曾读取运行画面并打开设置，未切换选项；这些画面不作为本报告的验收依据。此前截图在 `docs/reviews/settings-2026-11-05/`，不代表完整流程测试。

在工作区递归检索及盘符根目录、上级目录检查中，未找到 `AGENT.MD` 或 `AGENTS.md`，因此不能声称已遵守一份未取得的文件。当前按以下可读取规范执行；若后续提供该文件，应补做规则差异核对：

- `docs/决策记录.md`：Agent 不执行测试，由用户手动验收；以当前需求和实际文件为准。
- `UI_ASSEMBLY_STANDARD.md`：静态可编辑节点、独立原生子窗口、窗口外关闭与内部不穿透、浅目录结构。
- `excel/README.md`：玩家文本与参数以 Excel 为源，JSON 为导出结果。
- `docs/项目档案.md`：旧版设计文档存在过时信息，不据此判定当前功能缺失。

以下“文件确认”指实现路径可直接核对；“风险”指需要用户后续验证或产品决策，不能当作实测缺陷。P1 为本轮优先修复，P2 为下一轮完善，P3 为后续评估；本次未确认阻止玩家继续游戏的 P0 问题。

## 2. 设置应解决什么问题

本作是桌面常驻游戏。设置的首要任务是让玩家控制“是否打扰、出现在哪里、是否遮挡工作、退出后能否记住”。判断标准是可控、可预期、可恢复。

不应通过设置改变天气概率、作物收益或离线产出等经济规则；天气表现开关只改变画面与声音，不改变玩法结算。自动钓鱼、重复种植等生产决策继续留在对应玩法界面。

## 3. 当前功能盘点

| 功能 | 当前文件事实 | 评价 |
| --- | --- | --- |
| 设置入口 | `Main.tscn/Overlay/SettingsIcon/SettingsHitArea` 连接 `_open_settings()` | 路径完整；实际点击便利性待用户判断 |
| 窗口结构 | 独立 `SettingsWindow.tscn`，固定 520×465；控件为静态节点 | 符合可编辑方向，应保留现有木质美术 |
| 音乐 | 控制 `MusicManager`，默认开启，改变后请求保存 | 有效基础开关，但不等于全部声音 |
| 贴底 | `_stick_to_bottom` 为场景成员，初始为 true | 缺少持久化与完整位置模式定义 |
| 置顶 | 改原生窗口标记；记录 `always_on_top` 和用户修改标记 | 状态、应用与保存链路较完整；默认关闭有利于减少遮挡 |
| 语言 | 简体中文、English；独立写入 `user://language.txt`，随后重载主场景 | 选择持久化路径存在，但切换会打断界面上下文 |
| 显示屏幕 | 枚举显示器；Windows 辅助脚本获取名称，失败时可回退屏幕编号 | 有多屏基础；设备变化与长名称需完善 |
| 上下移动 | 每次增减 10 个桌面坐标像素，限制在可用区，并保存 | 有边界保护；缺少偏移数值、归零和禁用反馈 |
| 操作说明 | 内容场景有按钮和信号，窗口实例将按钮隐藏 | 玩家无法从设置访问，属于入口未交付 |
| 天气表现 | 数据与表现支持 standard / low / off | 设置没有对应控件，已有能力未开放给玩家 |
| 天气环境音 | 默认开启；雨声走 Weather 总线，有独立布尔偏好 | 设置没有对应控件 |
| 关闭 | 右上关闭和 Esc 路径存在；设置被排除出失焦关闭逻辑 | 与现行子窗口规范不一致 |

主要证据：`scripts/ui/main_ui.gd` 的 `_open_settings()`、`_select_language()`、`_apply_desktop_window()`、`_toggle_dock()`、`_change_display()`、`_dismiss_unfocused_subwindow()`；`scripts/autoload/music_manager.gd`、`text_db.gd`、`save_manager.gd`、`game_state.gd`；`scripts/world/weather_visual.gd`。

## 4. 玩家流程评估

1. **找到设置入口：基础完整。** 图标有独立点击节点；建议补充“设置”悬停提示。点击区的实际大小、透明区域误触不作静态验收结论。
2. **理解当前设置：需要优化。** 音乐、置顶容易理解；“贴底”和“移动”的关系没有说明，开关采用通用按钮而非明确的勾选状态。
3. **调整声音：控制不完整。** 可以关音乐，无法从设置关雨声或降低环境音量。
4. **调整位置：存在逻辑缺口。** 贴底关闭未形成自由位置模式，移动缺少数值与恢复入口。
5. **切换语言：基本路径存在，连续性不足。** 重载场景会关闭当前面板，场景局部状态重新初始化；具体玩法瞬时状态是否受影响需逐项核对，不推断数据丢失。
6. **离开设置：规则不一致。** Esc 与关闭按钮有实现，失焦关闭明确跳过设置。
7. **下次打开或重新启动：恢复规则不完整。** 音乐、置顶、屏幕、偏移有保存路径；贴底没有。语言独立保存，而多数偏好混在进度存档内。

## 5. 确定问题及优先级

### P1-01：贴底开关未实现玩家能理解的位置模式

**文件确认：** `_toggle_dock()` 只反转临时变量，开启时重新定位；关闭时没有解锁拖动或写入偏好。该变量只用于按钮文案与本函数；`_apply_desktop_window()` 不读取它，始终按底边与 `display_raise` 定位。重载主场景后变量恢复 true。

**影响：** “关闭贴底”没有形成稳定、可恢复的替代行为，切屏或移动仍使用底部计算。

**策划决定建议：** 第一轮将这一组明确为“底部停靠 + 距底部偏移”，保留上下调整；在自由拖动尚未实现前，隐藏贴底开关，避免暴露无完整行为的选项。若未来确需自由模式，再增加“底部停靠 / 自由放置”，分别保存位置，不复用一个临时布尔值。

### P1-02：玩家无法控制全部现有声音

**文件确认：** 音乐按钮只控制背景音乐；雨声由 `weather_ambient_enabled` 独立控制，默认 true，但设置中没有入口。这是控制覆盖不足，不应把“音乐关闭后仍有雨声”直接判作音乐开关失效。

**方案：** 本轮增加“环境音”开关及“一键静音”。静音覆盖所有游戏音频，取消静音恢复各项原有状态。后续按实际需求加入音乐、环境音音量，暂不为尚未存在的音效制作空控件。

### P1-03：设置窗口违背统一的外部关闭规则

**文件确认：** `_dismiss_unfocused_subwindow()` 遇到设置窗口直接返回；UI 规范要求原生子窗口失焦或窗口外点击后关闭。主窗口的交互入口在弹窗可见时还会跳过世界点击判定。

**方案：** 设置遵循其他子窗口的关闭约定；语言和屏幕下拉弹出列表是内部操作，不应被当作外部失焦。关闭仅结束面板，不暂停生产、不撤销已生效偏好。是否存在实际操作阻塞由用户后续确认。

### P1-04：移动缺少反馈和恢复动作

**文件确认：** 箭头固定 ±10，偏移有上下界，但没有当前值、恢复贴底按钮或边界禁用状态；每次移动直接写整个存档。

**方案：** 显示“距底部：N px”，提供上移、下移和“恢复贴底”。边界处禁用对应箭头，长按连续移动可列入第二轮。连续调整即时应用，合并延迟保存，避免每一步都写盘。“恢复贴底”只归零偏移，不修改置顶、声音或进度。

### P2-01：已有天气表现设置没有入口

**文件确认：** standard / low / off 已被天气表现层读取；偏好变更信号已定义并被监听，设置没有发出该修改的入口。

**方案：** 增加“天气特效：标准 / 简化 / 关闭”，复用现有实现和信号。关闭只影响表现，天气提示与经济效果继续按真实天气执行，并在说明中明确。“简化”当前主要降低粒子数量，不包装为已经验证的整机省电模式。

### P2-02：语言切换重载场景，且布局不适合长文案

**文件确认：** `_select_language()` 保存后切语言、重载主场景；`TextDB` 自身已有遍历更新静态文本与语言变更信号。标签采用固定偏移，例如屏幕标签预览写“屏幕”，运行时文本 ID 对应“显示屏幕”；“移动”对应“向上移动”，与双向箭头的组含义也不一致。

**方案：** 优先保留主场景与设置面板，更新静态文本及动态列表；若暂时必须重载，至少恢复到设置页并明确短暂刷新。文案统一为“显示器”“距底部偏移”，中文预览、文本 ID 和英文保持同一含义。长英文和设备名的溢出属于布局风险，未做实机确认。

### P2-03：设置作用域和重置边界不清楚

**文件确认：** 音乐、置顶、屏幕等保存在 `GameState.settings`；语言单独保存。创建新游戏会重建 GameState，因而偏好存在随进度恢复默认的路径；不是已经确认的所有重置入口行为。

**方案：** 音乐、语言、窗口位置等列为本机偏好，生产选择列为进度数据。未来“恢复默认设置”只重置偏好，并保留用户可访问的屏幕；“清空进度”维持独立危险操作和明确确认，不与设置恢复共用按钮。第一轮不必为此迁移全部存档。

### P2-04：键盘焦点缺乏清晰视觉反馈

**文件确认：** 打开弹窗后聚焦关闭按钮；`SecondaryButton.tscn` 的焦点样式为空，关闭按钮的焦点样式复用普通贴图。

**方案：** 为焦点提供可见边框或高亮，静态定义合理的 Tab 顺序；开关采用真实的持续选中状态，并同时显示“已开启 / 已关闭”。保留 Esc 关闭。键盘完整可达性、对比度和辅助技术支持均未验证，不宣称无障碍合规。

### P2-05：保存失败没有面向玩家的恢复反馈

**文件确认：** `save_game()` 可返回 false；切屏、移动和语言切换调用方不处理返回结果，音乐和置顶通过延迟保存。语言文件写入失败时同样没有面向玩家的提示。

**方案：** 即时生效与保存状态分开显示；成功保存后才显示“已保存”，失败时提示“本次已生效，暂未保存，可重试”。只在异常时明确打扰，正常连续操作不反复弹通知。

## 6. 需要补充核对的风险

| 风险 | 静态依据 | 后续处理 |
| --- | --- | --- |
| 断开显示器后回退到意外屏幕 | 保存屏幕索引；加载时仅做范围裁剪 | 记录设备标识并提供主屏回退；身份接口与映射方案交开发确认 |
| 分辨率、任务栏或 DPI 改变后的窗口位置 | 当前主要在启动及设置调整时重新应用；未找到相应专门刷新链路 | 用户核对热插拔、缩放、任务栏变化；不能据此断言必然越界 |
| 切屏后下拉选择与实际目标不同步 | 上下移动取当前屏幕并写入偏好，但没有刷新屏幕列表选中项 | 切屏、移动完成后统一刷新当前状态 |
| 显示器名称识别可能阻塞打开设置 | 打开设置时同步 `OS.execute()` 调用 PowerShell，结果缓存在内存 | 先显示屏幕编号，名称异步补充；耗时未测量 |
| 小屏或高缩放下内容可见性 | 固定 520×465，主要控件绝对定位，缺少内容滚动区 | 增项时采用静态分组和滚动区，用户确认实际可见面积 |
| 设备名和下拉框风格一致性 | 开关复用美术按钮，下拉框未见同等专用皮肤 | 延用木质样式补齐状态；不先投入整套重绘 |

## 7. 建议的设置结构

保持独立原生 Window 和现有木框；按三个静态分组排列，超出高度时仅内容滚动，标题与关闭入口固定。

| 分组 | 本轮或下一轮内容 | 交互原则 |
| --- | --- | --- |
| 声音与表现 | 静音、音乐、环境音、天气特效 | 即时生效；视觉关闭不改变收益 |
| 桌面显示 | 显示器、窗口置顶、距底部偏移、恢复贴底 | 偏移值可读；默认不置顶；安全回退 |
| 通用与帮助 | 语言、操作说明、恢复默认设置 | 语言使用本名；帮助不依赖短暂通知 |

不增加“应用 / 取消”双重流程：普通设置即时生效并自动保存；恢复默认需要一次清晰确认。关闭按钮标明关闭设置，不能让玩家误以为退出游戏。

“操作说明”建议复用现有静态按钮，打开可持续阅读的帮助面板；内容覆盖鼠标操作、自动生产、离线结算及窗口位置控制，具体规则从当前实现整理，不复用可能过时的早期说明文本。

## 8. 实施拆分与约束

**第一轮：行为闭环。** 解决四项 P1：明确底部停靠模型、环境音与静音、统一外部关闭、显示偏移并提供恢复。交付标准是“调得动、看得懂、关得掉、记得住”。

**第二轮：体验完善。** 开放天气表现、优化语言切换与布局、补帮助入口、焦点与保存反馈，并处理多屏恢复。

**第三轮：按反馈立项。** 音量滑杆、通知偏好、后台帧率、临时隐藏/托盘、自由放置模式。它们与常驻体验相关，但需要单独定义唤回方式、后台生产是否继续及资源预算，不能作为本次已确认缺陷，也不能直接承诺性能收益。清晰的“保存并退出”入口可在该轮评估，保留系统已有关闭方式。

开发约束：

- 布局在 `SettingsWindow.tscn` 与 `SettingsContent.tscn` 编辑，Main 只挂载窗口，不保存内部布局覆盖。
- 新分组、提示、数值、开关和帮助面板先有静态节点；运行时仅填数据、切状态、绑定事件。
- 不把所有交互逻辑继续堆入 `main_ui.gd`；可使用设置控制脚本管理状态同步，但不运行时拼界面。
- 新文案先补 `excel/文本.xlsx` 中英文，新可调参数写入对应 Excel 源表；不直接修改导出 JSON。
- 沿用现有素材和浅目录结构。替换临时贴底逻辑时同步清理失效引用；分割线与隐藏帮助节点需确认用途后保留或移除。
- 用户补充约束后仅继续静态文件阅读与文档产出，未执行导表、测试或功能实现；此前运行界面读取情况见第 1 节。

## 9. 交给用户的后续验收清单

以下是未来实现后的验收要求，本次均未执行，也不代表现版本已通过。

- 打开、关闭、窗口外点击与 Esc 行为一致；点击下拉列表不误关窗口，内部操作不触发地块或建筑。
- 音乐关闭只影响音乐；环境音关闭停止雨声；静音关闭全部声音，解除后恢复原偏好。
- 天气特效关闭不改变天气周期、增益、鱼池或生产结算。
- 上下移动后可见偏移数值，边界箭头正确禁用；恢复贴底只归零偏移。
- 同一设置关闭重开、语言切换、退出重进后状态一致；偏好不被创建新进度意外清除。
- 中文、英文和长显示器名不压住相邻控件；静态预览与运行文案含义一致。
- 单屏、双屏、负坐标副屏、断屏、不同 DPI、任务栏变化时，游戏及设置窗口始终可找回。
- 键盘可以到达所有可用控件，焦点可见，Enter/Space 修改对应选项。
- 保存失败有可理解的提示与重试；连续位置调整不刷屏。
- 用户能区分“恢复默认设置”“清空进度”“关闭设置”和“退出游戏”。

立项建议：以第一轮四项 P1 作为最小优化包，第二轮独立排期；本次交付止于评估与策划。
